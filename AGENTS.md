# BowlBuster

BowlBuster studies Bowl Storage, a memory-corruption glitch in *The SpongeBob SquarePants Movie*: it predicts where the glitch's writes land, describes their effects and searches for chains of loads that reach a wanted one. It is in early development.

## Repository layout

| Path | What it is |
|---|---|
| `src/BowlBuster/` | The library. Domain code goes here. |
| `src/BowlBuster.Cli/` | The console application. |
| `tests/BowlBuster.Tests/` | xUnit v3 tests. |
| `catalog/` | The rule catalog: YAML files, licensed CC0. |

Run these from the repository root:

```
dotnet build
dotnet test
dotnet format
```

Warnings are errors, and `dotnet format --verify-no-changes` must pass.

## C#

- .NET 10 and C# 14. Nullable reference types and `ImplicitUsings` are on.
- Use modern syntax where it reads well: `field`, null-conditional operators, spread elements, collection expressions, primary constructors, and expression-bodied members for simple members.
- Compare compile-time constants with `is`, `not`, `or` and `and` patterns.
- Use `nameof()` rather than a string literal for a type name.
- Prefer LINQ and fluent APIs where they read well.
- Keep code clean, succinct and simple. Do not build for requirements nobody has.
- Comment sparingly. If code needs a comment to be understood, change the code first.
- Public APIs get thorough XML documentation: `<see>` for cross-references and keywords, `<inheritdoc/>` for inherited members, and a `using` rather than a fully qualified name inside `<see>`. A public member of the library without documentation fails the build.

## Tests

- Arrange, Act, Assert, in that order. Act and Assert may share a line when that reads better.

## Commits

- Keep commits small and focused, one concern each, with an imperative message.
- Do not add attribution lines: no `Co-authored-by` trailers and no "generated by" marks.
- An agent commits only if its operator has said it may. Otherwise it stops after each logical step and leaves the changes uncommitted.

## Rules

- **Clean room.** The repository holds no game files or game data. Names, addresses, sizes and other dimensions are fine; extracted content is not.
- **Licensing.** Code is MIT. The catalog is CC0, and each of its files carries an SPDX header. Run `reuse lint` before committing license changes.
- **AI use.** Contributions, including those made by agents, follow the [AI contributions policy](AI_POLICY.md).
- Keep documentation, comments, and this file current with the code.
